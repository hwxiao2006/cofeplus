## 1. 背景

7-27 版重设计把录入流程改成了"设备工作单"（一台设备连续录入、可点击编辑），解决了流程混乱问题。但字段仍是一刀切的通用字段（部件名称 / 序列号 / 硬件版本 / 固件版本 / 参数备注），部件的选配信息只能写进自由文本，没有结构。

新版线下表《QR-PD-101-A3 模组信息表》把纸面表升级为 **18 个模组，每个模组有明确的选配项清单**（如咖啡机型号三选一、机械臂的控制箱/单臂拉花/电爪各自可选）。同时提出三条业务要求：

1. 表里的字段组合可有删减功能；
2. 已有的字段亦可删减组合；
3. 选了"吧台"后录入字段自动减少（如：没有压盖和落杯）。

补充要求：**序列号支持扫码录入**，且扫码方式自适应（飞书内 / 手机浏览器自动选择）。

## 2. 已确认的设计决策

以下均经逐轮澄清确认：

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 数据结构 | 结构化分项照模板填——18 个模组各自定义选配项，录入界面按模板渲染勾选，不再自由填空 |
| 2 | 字段增删的实现层 | 录入时按设备裁剪（前端模板 + 可去掉/加回模组），不做后台模板管理系统 |
| 3 | 吧台裁剪机制 | 预设默认（自动去掉落杯、压盖）+ 一线可手动改（加回或再去掉其它模组） |
| 4 | 飞书表落法 | 沿用"一个模组一行"；模组特有选配收进两个新字段，不逐项开列 |
| 5 | 选配的存储形态 | 两列并存：「配置详情」给人看的中文说明 + 「配置数据」底层精确记录（供编辑回填） |
| 6 | 录入界面布局 | 逐模组向导（stepper），手机优先；顶部进度 + 步骤芯片，底部上一个/下一个 |
| 7 | 扫码方式 | 自适应三级：飞书容器内→飞书自带扫码；手机浏览器→网页调摄像头扫；都不行→手动输入 |
| 8 | 设备型号字段 | 新增（不复用现有"设备版本号"，老字段与老数据不动） |
| 9 | 18 模组清单与裁剪规则 | 已按可视化清单确认（见 §3、§4） |

## 4. 裁剪规则

**设备类型驱动的预设：**

- 咖啡亭：默认带 1–14、18 共 15 个必备模组；15 3D印花机、16 顶部射灯、17 空调为选配，默认不勾。
- 吧台：在咖啡亭基础上再默认去掉 6 落杯机构、7 压盖机构。

**手动增删（业务要求 1、2）：**

- 向导前的"模组清单"屏列出全部 18 个模组，按预设勾好；一线可手动去掉任何默认模组（如这台确实没有制冰机），也可加回被预设去掉的（如某吧台确实带压盖）。
- 被去掉的模组不进向导、不写入飞书表。
- 序号恒等于模板序号（落杯永远是 6 号），不因裁剪重排——保证跨设备可比。

**编辑已有设备时的删除：** 在模组清单里去掉一个已有数据的模组时，弹确认（"该模组已有记录，去掉将删除这条记录"），确认后删除对应行。不做静默删除。

## 5. 飞书表变更

沿用现有两张表（同一 app 下的多维表格），只加字段、不删不改老字段，老数据零影响。

### 表一 · 咖啡亭台账（一台设备一行）

新增 3 个字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| 设备类型 | 单选：咖啡亭 / 吧台 | 对应 A3 表顶部勾选，驱动裁剪预设 |
| 设备型号 | 文本 | 对应 A3 表头"设备型号"；与现有"设备版本号"并存，互不影响 |
| 调试员 | 文本 | 对应 A3 表头"调试员" |

现有字段（设备编号、设备名称、设备版本号、出厂日期、所属区域、现场地址、设备状态、原始资料、部件配置关联）全部保留不动。

### 表二 · 部件配置（一个模组一行）

新增 2 个字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| 配置详情 | 文本 | 给人看的中文摘要，如「型号 AUBO六轴(C5)；控制箱 小控制箱；单臂拉花 无；电爪 高配版」。在飞书里直接读 |
| 配置数据 | 文本 | 底层精确记录（结构化 JSON），编辑时据此准确回填勾选项。日常不用看 |

现有字段（设备编号、部件名称、序号、部件序列号、硬件版本号、固件版本号、参数与备注、资料状态、部件照片、附件、所属设备关联）全部保留。写入映射：

- 选配项与参数 → 同时写「配置数据」（精确）与「配置详情」（摘要）；
- 模组固件 → 仍写现有「固件版本号」列（电视机的两个版本号合并为「上位机 x / 下位机 y」，同时在配置数据里分开存）；
- 序列号/MAC → 仍写现有「部件序列号」列；
- 自由备注 → 仍写现有「参数与备注」列（结构化参数不再挤在这里）。

变更操作路径：编辑两份 capability JSON 增加字段声明 + 飞书表实际加列 + 云端重新配置。属实施阶段动作，列入计划。

## 6. 录入界面

整体沿 7-27 版流程骨架升级，分三屏：

### 6.1 首屏（新建/进入设备）

- 顶部选**设备类型**：咖啡亭 / 吧台（大按钮二选一，带说明"吧台自动去掉落杯/压盖"）。
- 整机信息：设备编号（带 📷 扫码）、设备型号、出厂日期、调试员。设备编号命中已有台账时提示"设备已存在"，回填整机信息并可继续补录。
- 底部「开始逐模组填写 →」。

### 6.2 模组清单屏（裁剪入口）

- 18 个模组按预设勾选态列出（吧台预设已去掉落杯/压盖；三个选配默认不勾）。
- 每项可勾/去勾；已有数据的模组去勾时弹确认（见 §4）。
- 已填完的模组显示 ✓ 与配置摘要一行；点任意模组可直接跳入该模组填写（支持跳填与断点续填）。
- 底部「按此清单开始 →」。

### 6.3 逐模组向导屏

- 顶部：设备编号 + 「第 x / N」（N 为裁剪后数量）+ 细进度条 + 可横滑的步骤芯片（已填 ✓ 绿、当前深色、未填灰；点芯片可跳）。
- 中部：该模组的选配项（圆角单选胶囊）、参数小输入、部件序列号（带 📷 扫码）、固件版本号、备注、拍照。条件显隐按模板规则（如选四轴2140 才出现夹爪距离参数）。
- 底部：「← 上一个」「下一个 →」；最后一个模组为「完成」。每个模组点"下一个"即保存该模组（沿用工作单的"边填边存"语义，不做最后一次性提交），中途退出不丢已存数据。
- 完成后回到设备工作单总览（7-27 版已有），可见整台清单与编辑入口。

### 6.4 编辑已有模组

沿用 7-27 版编辑入口（工作单清单行点击进入），编辑页渲染与向导相同的模板字段，用「配置数据」回填勾选项。存量老数据没有配置数据时，通用字段正常回填，选配项为空待补，原「参数与备注」原文保留展示。

## 7. 扫码自适应

三级自动降级，一线无感：

1. **飞书容器内**（含飞书内打开的网页）：调飞书自带扫码（JSAPI）。体验最好，逆光/损码识别强。
2. **普通手机浏览器**：网页调摄像头扫（getUserMedia + JS 识码库）。要求 HTTPS——线上域名满足；本地 localhost 调试摄像头受限，真机测试需走线上地址。
3. **兜底**：手动键盘输入 / 扫码枪（扫码枪本质是键盘输入，天然可用）。

运行时探测顺序：检测飞书 JSAPI 可用 → 用飞书扫码；否则检测摄像头可用 → 网页扫码；否则只显示手输框。扫码按钮始终伴随手输框，扫码失败随时可手输。

**待验证（进实施计划第一步）：** 妙搭平台是否放行 ① 飞书 JSAPI 鉴权调用；② 第三方识码 npm 包；③ 飞书容器内 WebView 的摄像头权限。三者至少通一条即可上扫码；全不通则本期先上手输+扫码枪，扫码留待平台确认后补。

## 8. 数据写入逻辑

- 复合键沿用：设备编号 + 部件名称 + 序号 定位行；命中则更新、未命中则新建（与现状一致）。
- 「配置数据」为单层键值 JSON，键为选配项/参数的中文名，值为所选文案或输入值，例：`{"型号":"AUBO六轴(C5)","控制箱":"小控制箱","单臂拉花":"无","电爪":"高配版"}`。
- 「配置详情」由配置数据按模板顺序生成：`键 值；键 值；…`。两列同一次写入，保证一致。
- 整机信息（设备类型/设备型号/调试员/出厂日期等）随每次模组保存一并写台账（沿用 7-27 版"工作单当前值为准"语义）。
- 资料状态沿用现有三态与默认逻辑，不变。

## 9. 错误处理

- 扫码失败/无权限：静默降级到下一级方式，不弹错误打断；扫码按钮旁始终有手输框。
- 模组保存失败（网络/接口）：停留当前模组，顶部红条提示可重试；已存模组不受影响。
- 去勾已有数据模组：必须确认弹窗，列明将删除的记录；删除失败提示并保持勾选态。
- 老数据（无配置数据的行）进编辑页：不报错，选配项空白可补填，保存后补全两个新字段。

## 10. 测试要点

- 模板渲染：18 个模组各自字段正确；条件显隐（四轴夹爪距离、四路奶固件）正确。
- 裁剪：咖啡亭/吧台预设正确；手动增删生效；序号恒定不重排；去勾已有数据模组走确认+删除。
- 写入：配置详情与配置数据一致且与勾选一致；固件/序列号/备注写入老列；复合键更新不重复建行。
- 回填：编辑页按配置数据准确回填；老数据行兼容。
- 扫码：飞书内、手机浏览器、无摄像头三种环境各自走对分支；手输兜底始终可用。
- 台账：设备类型/设备型号/调试员随保存写入；老字段不受影响。
