# 部件配置采集流程重设计 · 设计文档

- 日期：2026-07-27
- 状态：已获用户确认（基于 v2 可视化 mockup）
- 目标应用：机器人咖啡亭配置采集（妙搭云端全栈应用，app_id `app_17artejsm44`）
- 配套 mockup：`docs/superpowers/mockups/2026-07-27-part-collection-redesign.html`
- 本地参考代码：`cofeconfig/`（由 `lark-cli apps +init` 克隆，仅作阅读参考；实际改动须通过妙搭云端会话进行）

## 1. 背景与问题

应用用于把线下《机器人咖啡亭信息表》纸质/Excel 表格数字化。用户反馈"录入设备配置的流程不清楚、页面设计混乱"。经代码分析与逐轮澄清，确认四个混乱点：

1. **改已有部件容易出错**：新增页命中"设备编号+部件名称+序号"复合键时静默转为更新，但表单不回填现有值，空字符串字段会无条件覆盖原数据（仅"资料状态"有 dirtyFields 保护）。
2. **找不到修改入口**：全应用没有编辑入口。设备台账页的部件列表是纯展示，首页最近部件列表也不可点击。
3. **填表页面本身乱**：Step 2 顶部堆叠两条视觉相似的提示条（设备状态 + 部件状态）；7 个字段 + 附件在一个网格里平铺无分组。
4. **两步流程走向别扭**：每录一件部件都要走完 Step 1 → Step 2 → 成功弹窗，与真实作业方式（一次录完一整台设备约 16 件）严重错位。

### 线下表格实样分析（RCK001，2021-03-25）

线下一张表 = 一台设备：

- 表头一行设备级信息：设备名称、设备编号、设备版本号（如"3.0室内超高版"）、出厂日期。
- 下方 16 行部件明细：序号 1–16 连续编号；字段为部件名称 / 部件序列号 / 硬件版本号 / 固件版本号 / 备注。
- 数据规律：
  - 部件名称高度标准化（咖啡机、机械臂、制冰机、出杯机构、落杯机构、压盖机构、后道粉后道颗粒、前道粉、前道浆、冰箱、水路总成、侧面屏、点单屏、广告屏……），存在同名多台件（"出杯机构1#（左）/2#（右）"）。
  - 硬件版本号几乎全为同一值（V1R1）——纸面上是重复抄写。
  - 固件版本号大量留空；备注承载复杂运行参数（多行压力值、时间参数等）。

**核心洞察**：技术员的真实作业单位是"一台设备"，不是"一个部件"。重设计以此为中心。

## 2. 设计总览

| # | 改动 | 说明 |
|---|------|------|
| 1 | Step 2 升级为"设备工作单" | 设备信息卡 + 已录部件清单 + 录入表单同屏；提交不弹窗，连续录入 |
| 2 | 新增编辑页（单步直改） | 全字段预填充；台账页与工作单清单两个入口 |
| 3 | 台账页部件列表可点击 | 整行点击进入编辑页 |
| 4 | 共用表单组件 | 新增与编辑共用一份字段分组、校验、上传逻辑 |
| 5 | 状态提示条合并 | 两条相似提示合并为一条，按情境给单一文案 |
| 6 | 录入加速细节 | 部件名称预置清单、序号自动建议、硬件版本号沿用上一件 |

保持不变：Step 1（输入设备编号查询台账）结构不变；"命中复合键静默转更新"的现有行为保留（但提示更醒目）；新增流程的成功语义改为列表内联反馈。

## 3. 详细设计

### 3.1 新增流程 Step 2 · 设备工作单（核心改造）

进入 Step 2 后，页面围绕"这台设备"组织为三个区域：

**① 设备信息卡（顶部横向）**
- 设备编号：锁定展示（Step 1 已确认），不可改。
- 设备名称、设备版本号、出厂日期：可编辑字段，当场补全。对应线下表头。
- 右侧徽标显示"设备已存在 / 新设备"。
- 新设备不再默默写入"待完善"占位名——技术员在工作单上直接填真实名称与版本。设备级字段在每次保存部件时随部件一并写入台账（以工作单当前值为准），无需单独的"保存设备"按钮。

**② 已录部件清单（左栏）**
- 实时展示本台设备已录入的全部部件：展示行号（圆圈数字，整台设备连续编号，同线下表格 1–16）、部件名称、部件序列号、资料状态徽标。
- 点击任一件进入编辑页（同 3.3 的编辑页）。
- 刚保存的部件以绿色高亮出现在列表尾部，替代成功弹窗。

**③ 录入表单（右栏）**
- 永远代表"下一行"。字段按语义分组（见 3.4）。
- 提交按钮文案："保存，录下一件"。提交成功后：清单新增一行 → 表单重置（保留沿用值）→ 焦点回到部件名称。不弹成功对话框。
- 底部两个流程出口：
  - "完成本台设备"→ 返回设备台账页并定位到该设备。
  - "换一台设备"→ 返回 Step 1。

### 3.2 录入加速细节

**部件名称 · 预置清单下拉**
- 下拉展示标准部件清单（以 RCK001 实样 16 项为初始清单），本设备已录入的项打"已录"标。
- 支持直接输入清单外的名称（自由文本，不强制从清单选）。
- 清单兼作完成度参照：录完前扫一眼还有哪些未录。
- 清单维护方式：初期作为应用内静态配置；后续如需运营可维护再演进（不在本次范围）。

**序号自动建议**
- 部件名首次出现 → 序号默认 1。
- 同名部件已存在 → 自动建议下一个可用序号（如"出杯机构"已有序号 1，建议 2）。
- 用户改回已占用序号 → 显示橙色提示条"本设备下已有「XX · 序号 N」，保存后将更新原记录（原资料状态：XX）"，保存即更新那条记录（保留现有静默转更新行为，但不再无声）。
- 注意：表单"序号"语义是"同名部件第几台"（对应数据表的复合键），与清单的展示行号（整台设备连续编号）是两个概念，互不冲突。

**硬件版本号 · 沿用上一件**
- 保存一件后，下一件的硬件版本号自动预填上一件的值（实样中 16 件几乎全为 V1R1），可随时修改。
- 字段旁给"沿用上一件"小标签提示来源。

### 3.3 编辑部件页（新路由）

- 路由：新增独立编辑路由（如 `/parts/:recordId/edit`）。
- 入口：设备台账页部件列表（整行点击）+ 工作单已录清单（整行点击）。
- 结构：单步直改，不经过"输入设备编号"。顶部一条固定编辑上下文提示："正在编辑「设备编号 · 部件名称 · 序号 N」"，并注明设备编号固定不可改（不提供改绑设备能力）。
- 表单：与录入表单同一套组件，全字段预填充现有值。所见即所存：用户看到什么就是什么，不改即保持，提交时全字段回写。这从结构上消除"提交后意外清空"的风险，不再需要 dirtyFields 式的部分字段保护。
- 底部："取消返回"（不保存）+ "保存修改"。
- 保存后：返回来处（台账页进入的回台账页；工作单进入的回工作单），顶部滑入绿色轻量提示条"已保存「XX」的修改"，数秒后自动消失，列表即时刷新。不弹成功对话框。

### 3.4 共用表单组件与字段分组

抽出一个共用的部件表单组件，供"工作单录入"与"编辑页"两处使用，收敛字段定义、校验规则（一份 zod schema）、上传/预览逻辑。字段按语义分组：

1. **标识信息**：部件名称（必填，预置清单）、序号（必填，自动建议）、部件序列号（选填）
2. **版本信息**：硬件版本号（选填，沿用上一件）、固件版本号（选填）
3. **资料状态与备注**：资料状态（必填，默认"待核验"）、参数与备注（选填，占位文案给出实样示例如"出冰时间：4s；重量AD值：466"）
4. **附件**：部件照片/附件（选填）

每组一张卡片、左侧主色小竖条 + 组标题。两处的差异仅为：初始值（空 vs 现有记录）、顶部提示文案、提交行为（连续录入 vs 保存返回）。

### 3.5 状态提示条合并

原 Step 2 顶部的"设备状态 + 部件状态"两条相似提示合并为一条，按情境单一文案：

| 情境 | 样式 | 文案示例 |
|------|------|----------|
| 新增 · 设备已存在 | 蓝色信息 | 设备 RCK001 已存在，接下来录入的部件都归属这台设备 |
| 新增 · 命中已有部件 | 橙色警示 | 本设备下已有「机械臂 · 序号 1」，保存后将更新原记录（原资料状态：待补充） |
| 新增 · 新设备 | 蓝色信息 | 设备 RCK009 为新设备，保存首个部件时同步创建设备台账 |
| 编辑页 | 主题色固定 | 正在编辑「RCK001 · 机械臂 · 序号 1」 |

工作单形态下，"设备已存在/新设备"信息主要由设备信息卡的徽标表达，表单区仅在命中已有部件时出橙色警示条，避免重复。

### 3.6 视觉

沿用应用现有暖咖橙主题：主色 `hsl(28 68% 53%)`、卡片圆角 `1rem`、现有字体栈（Inter / PingFang SC）与阴影体系。不引入新的视觉语言。

## 4. 明确不做 / 已知保留

- **不改 Step 1 结构**：输入设备编号 → 查询 → 进入 Step 2 的两步结构保留。
- **静默转更新行为保留**：新增时命中复合键仍转为更新，仅提示升级为醒目的橙色警示条。
- **不提供改绑设备**：编辑页设备编号固定。
- **Excel 批量导入不在本次范围**：本次为手工录入体验重设计；批量导入线下表格可作为后续独立课题。
- **首页最近部件列表暂不加编辑入口**：编辑入口收敛在台账页与工作单两处。
- **顺手清理**：`PartCollectionPage.tsx` 中未被引用的 `handleBackToHome` 死代码，实施时视云端改动范围一并清理。

## 5. 错误处理

- 工作单内单件保存失败：表单原地保留已填内容，红色提示错误原因，可重试；已录清单不变。
- 设备级字段保存失败：设备信息卡内联提示，不阻塞部件录入。
- 编辑页保存失败：停留在编辑页并提示，不返回列表。
- 附件上传失败：单文件级错误提示，不影响其他字段提交。

## 6. 测试要点

- 新增：新设备首件保存 → 台账创建且设备名称为用户所填（非"待完善"）。
- 新增：连续录入多件 → 清单逐件增长、表单重置、硬件版本号沿用、无弹窗打断。
- 新增：同名部件 → 序号自动建议下一号；改回已占用序号 → 出橙色警示，保存后原记录被更新。
- 编辑：从台账页/工作单两个入口进入 → 全字段预填充正确；不改直接保存 → 数据不变（无字段被清空）。
- 编辑：保存后返回来处 + 轻量提示 + 列表即时刷新。
- 提示条：四种情境文案与样式各自正确，同屏不出现两条堆叠。
- 预置清单：已录项打标正确；清单外自由输入可正常保存。
