① 当前问题

当前 selectRole(roleId) 一点卡片就同时做三件事：覆写 selectedRoleId、改摘要条文案、调 applyRolePermissions() 把所有权限 checkbox 推平。带来三个体验问题：

  1. 看不到原有角色。编辑「张店长」时只剩"已选择：运维人员"，原本是哪个角色彻底消失。
  2. 自定义权限被静默丢弃。橙色提示里的 +N/-M 微调，换角色时一个确认都没有，全部清掉。
  3. 「重新选择」语义错位。实际是把 role 置成 custom 并隐藏摘要条 —— 既不还原角色也不清空权限。

② 设计目标

  • 任何时候都能看到当前角色，包括"自定义"也算一种状态。
  • 切换是两步动作：点卡片 = 进入"待确认"，告诉用户影响，再让用户决定。
  • 保留撤销路径：确认后仍可在 toast 期内一键回滚。
  • 不动数据模型与 shared 文件：只动 staff-management.html 单文件。

④ 状态机 & 数据

变量含义
committedRoleId已确认的角色（写入员工记录用）
pendingRoleId待确认目标角色，null 表示无切换中
lastCommitSnapshot{ roleId, permissions[], moduleScopes } 撤销用

selectedRoleId 保留为 alias = pendingRoleId ?? committedRoleId，既有读取逻辑无需大改。

⑤ 代码改动清单

仅改 staff-management.html 一个文件。

HTML（约 +25 行）

  • 删除 #roleSummaryBar
  • 新增 #roleCurrentBanner / #roleSwitchPreview / #roleUndoToast 三个容器

CSS（约 +60 行）

  • .role-current-banner · .role-switch-preview · .role-undo-toast
  • .role-card[data-pending="true"] 虚线橙边 + 黄角标

JS

改: selectRole → requestRoleSwitch（只准备 pending，不应用权限）
新: confirmRoleSwitch() / cancelRoleSwitch() / undoRoleSwitch()
新: renderRoleSwitchPreview() / renderCurrentRoleBanner()
改: renderRoleCards() 支持 selected + pending 双态
改: fillStaffForm 进入时直接 commit 该员工原角色
删: resetRoleSelection() 及 HTML 中"重新选择"按钮

测试

  • 状态 B → C：点新卡片后权限树 checkbox 不变，对比条显示"原 → 新"
  • 状态 C → D：确认后权限树更新，撤销 toast 出现，点撤销恢复原状
  • 状态 C → E：取消后回到 B，pendingRoleId 清空

⑥ 不做的事

  • 不引入 modal-in-modal 确认弹窗
  • 不引入多步撤销栈（只支持最近一次）
  • 不动 role-definitions.js / permissions-registry.js
  • 不改 4 个角色模板的权限明细

预估总工作量：~2.5 小时（单文件改动 + 测试 + 手测）。

⑦ 用户已拍板的决策

#决策点选定

Q2b「当前角色」条上的「已微调」徽标彻底砍掉；微调统计交回原有橙色 .permission-customization-hint
Q3微调警告位置（C 状态）单独一行黄色警告（默认保留）
Q4custom 起点切角色走完整两步（默认保留）

新增的 3 个 regression 测试

  • 回填不触发切换 UI：mock targetStaff.role = { id: 'super_admin' }，调 fillStaffForm 后断言#roleCurrentUndoBtn hidden、lastCommitSnapshot === null
  • 手动改权限后撤销失效：confirm 切换后点 permission checkbox，断言撤销按钮消失
  • 关闭弹窗再打开不残留：连续两次 fillStaffForm，断言撤销按钮不会"穿越"
