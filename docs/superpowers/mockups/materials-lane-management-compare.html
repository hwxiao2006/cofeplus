货道管理逻辑改造比较

这次不是单纯换文案，而是把“物料管理”切成“货道管理”。每张卡片代表一个具体货道，货道一对一关联一个物料；发货、补充、发货单都要跟着切语义。这里把 3 种改法并排给你看。

当前新约束：6 个货道大类
每个货道只关联 1 个物料
编辑货道名称需要独立权限
A

最小改名版

主页面看起来像货道页，但发货页和发货单底层仍然偏“物料语义”。上线最快，但后面继续演进会更绕。

优点

改动小，最快能落。

代价

主页面是货道，发货页和发货单还是物料，三页语义会继续打架。

B

统一货道模型版

3 个页面都切成“货道主语”，把货道名称、关联物料名称、编码、余量和权限放到同一套模型里。范围适中，后续最好延展。

权限

可额外拆一个“编辑货道名称”权限，只影响改名入口，不影响发货 / 补充能力。

C

完整货道主档版

除了 3 个页面一起切语义，再补货道主档、批量编辑、解绑重绑、配置台账。最彻底，但明显超出这次页面改造范围。

当前建议：B。它能把 3 个页面统一到“货道主语”，又不会把范围一下拉到主档系统。
